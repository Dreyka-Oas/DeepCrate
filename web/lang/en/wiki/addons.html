For other mods

Twelve points are open, and nothing the mod ships is a special case it keeps for itself: every tier, module, cell, sort order and tooltip line goes through the same calls yours do.

fabric.mod.json"entrypoints": {
  "deepcrate": ["com.example.slatecrate.SlateCrateAddon"],
  "client": ["com.example.slatecrate.SlateCrateAddonClient"]
}

DeepCrateAddon has two methods, which are two passes of the mod's own start-up. onDeepCrateConfig() runs before the settings file is read, onDeepCrateInit() once the six shipped tiers are in place and before anything reads a registry.

The twelve points

PointWhat it adds
registerTiera crate, with its block, its rows and its columns
registerModulea capacity module, pointed at an item tag
registerRowModulea module that buys rows rather than capacity
registerModuleSlota cell on the module tab, which grows with it
onTierRegistereda call whenever a tier is registered after yours
CrateLayoutCallbackthe last word on rows per page and page count
CrateCapacityCallbackthe last word on what a slot holds, item by item
ConfigSchema.registerHolderyour own options, in the same settings file
ConfigBounds.registerGroupthe range each of them is clamped to
registerSortOrdera sort button, with its icon and its comparator
CrateScreenCallbacka widget on the crate screen
CrateTooltipCallbacka line in the tooltip of a crate slot

A tier in three lines

onDeepCrateInit()DeepCrateApi.registerTier(new CrateTier(id("slate_crate"), 10, 9, block));
DeepCrateApi.registerModule(new CrateModule(id("module_1024"), 1024, itemTag("module_1024")));
DeepCrateApi.registerRowModule(new RowModule(id("module_triple_row"), 3, itemTag("module_triple_row")));

A module points at an item tag rather than at one item, so adding your item to deepcrate:module_512 makes it a module with no code at all.

What stays closed, and why

A kind of crate stays Java. A tier carries a block, blocks go into the registry while the game loads its mods, and that registry is frozen long before the first data file is read: a crate declared in JSON would arrive with nothing to stand on.

The layout event has the last word on paging, but not on hiding rows. A layout whose pages cannot cover the crate is refused, the balanced one takes over, and the reason is logged.

What bites first

The screen hands you a CrateScreenArea: the panel's corner, its size, a way to add a widget, and keepClickable. Name through that last one any rectangle you draw past the edge of the panel. The game counts a click outside a container screen as a click into the world, and releasing one there throws on the ground whatever the player is carrying.

onScreenInit fires again on every layout, which includes every window resize, and the screen throws its widgets away between two of those. Add yours again rather than keeping one across calls.
