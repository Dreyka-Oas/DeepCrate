For other mods

Twelve points are open, and nothing the mod ships is a special case it keeps for itself: every tier, module, cell, sort order and tooltip line goes through the same calls as yours.

The twelve points, and what each one adds
PointWhat it adds
registerTiera crate, with its block, its rows and its columns
registerModulea capacity module, pointed at an item tag
registerRowModulea module that buys rows rather than capacity
registerModuleSlota cell on the tab, which grows with it
onTierRegistereda call for every tier registered after yours
CrateLayoutCallbackthe last word on rows per page and page count
CrateCapacityCallbackthe last word on what a slot holds, item by item
ConfigSchema.registerHolderyour own options, in the same settings file
ConfigBounds.registerGroupthe range each of them is pulled back into
registerSortOrdera sort button, with its icon and its comparator
CrateScreenCallbacka widget on the crate screen
CrateTooltipCallbacka line in a crate slot's tooltip

The entry point

DeepCrateAddon has two methods, which are two passes of the mod's start-up. onDeepCrateConfig() runs before the settings file is read, onDeepCrateInit() once the six shipped tiers are in place and before anything reads a registry. A module points at an item tag rather than at a precise item, so adding yours to deepcrate:module_512 makes it a module without a line of code.

A whole addon

Here is everything it takes to add a crate and a capacity module, with no mixin and nothing to ask for. The entry point is declared in your own fabric.mod.json:

fabric.mod.json"entrypoints": {
  "deepcrate": ["com.example.slatecrate.SlateCrateAddon"]
}

Then the class itself. onDeepCrateInit() runs once the six shipped tiers are in place, before anything reads a registry:

SlateCrateAddon.javapublic final class SlateCrateAddon implements DeepCrateAddon {
    private static final String NAMESPACE = "slatecrate";

    @Override
    public void onDeepCrateInit() {
        Identifier crate = Identifier.fromNamespaceAndPath(NAMESPACE, "slate_crate");
        DeepCrateApi.registerTier(new CrateTier(crate, 10, SlateCrateBlocks.SLATE_CRATE));

        Identifier module = Identifier.fromNamespaceAndPath(NAMESPACE, "module_1024");
        DeepCrateApi.registerModule(new CrateModule(module, 1024, TagKey.create(Registries.ITEM, module)));
    }
}

Ten rows of nine slots, and a module lifting every slot to 1024. The module points at an item tag carrying its own name, so any item added to slatecrate:module_1024 becomes that module with nothing more written. Adding yours to deepcrate:module_512 works the same way, and then asks for no Java at all.

What stays closed, and why

A tier stays Java. It carries a block, blocks enter the registry during mod loading, and that registry is frozen well before the first data file is read: a crate declared in JSON would arrive with nothing to stand on.

The layout event has the last word on pagination, but not on hiding rows. A layout whose pages do not cover the crate is refused, the even split takes over, and the reason is written to the log.

What bites first. The screen hands you a CrateScreenArea: the corner of the panel, its size, a way to add a widget, and keepClickable. Declare through that last one any rectangle drawn beyond the panel's edge, because the game counts a click outside a container screen as a click in the world, and releasing one there drops whatever the player is holding.

Where to report what breaks

The repository issues, github.com/Dreyka-Oas/DeepCrate/issues, the same address as the button at the foot of the home page. An entry point that moved without being announced is declared there like anything else, and the defects already known sit there open or closed in plain sight rather than in somebody's inbox.

The licence, for whoever reuses the code

The mod is not open source. Playing it and passing it on unmodified is free, selling it never is, and reusing the code or publishing a fork asks for written permission, which is usually given. The full text travels inside the downloaded file, and it is that text that governs rather than this page. Writing an addon against the twelve points above needs no permission at all: that is what they are for.
